# Roadmap

What is next, in build order: groundwork first, so the features on top stay small. One rule on every engine, emulated where an engine lacks it, refused only where it cannot be done.

## After 1.0

Additive: an entity that declares nothing keeps every capability, so none of this breaks code written for 1.0.

- **Value types.** `.of(Type)` on a string, number or date builder, `f.column('date').of(Temporal.PlainDate)` or `f.decimal(12, 2).of(Money)`, `Type` being any `{ from(text) }` that parses what its value's `toJSON()` prints. A codec per field, worked out at registration, converts a value to the column's own JS value at each edge (a write, a compared operand but not a pattern, a read, an aggregate, a cursor, a default), so no dialect learns of it; uql's types never name Temporal, so a polyfill works. Waits for a second app that needs it: the one measured has one field for it.
- **Polymorphic entities.** Single-table inheritance: a base declares a discriminator field, each subclass the value it stores, `@Entity({ discriminator: 'card' })` or `defineEntity({ extends, discriminator })`. A subclass's statements are held to its value as a filter is, and an insert is given it as a tenant is; a base's read answers each row as its subclass, typed as the union. A subclass's own fields are nullable columns of the one table. Its data form is the discriminator field and value, so it travels in the schema document. Table-per-type waits for an app that needs it: it is a join on every read.
- **Recursive reads (CTEs).** What a CTE is used for, without spelling one: a tree read through a self-relation, `$populate: { children: { $recursive: true } }` (or `{ $depth: 5 }`), and its filter form, `$where: { ancestors: { ... } }`. `WITH RECURSIVE` on SQL, `$graphLookup` on MongoDB, so the rule holds on every engine; a cycle stops at a row already reached. A named, reused subquery is not planned: computed fields and `$exists` cover it. Open: how a recursive relation is declared, and its result type's cost in `ts.perf`.
- **Procedures.** Custom logic beside the ops, on the same protocol, context, middleware and `security` filters: `serve(Post, { procedures: { publish: write({ input, run }) } })` for an entity's, `createApi({ procedures: { stats: read({ run }) } })` for the rest. `input` is any Standard Schema, validated before `run`, which gets the querier and the context. `read` takes `GET ?q=`, `QUERY` or `POST` and acquires a querier; `write` takes `POST` and runs in a transaction. The wire is `{base}/:entity/:name` and `{base}/rpc/:name`, a name never shadowing an op, and the client calls `db.call(Post, 'publish', input)`. [Open in the API layer](api-layer.md#open).
- **The schema document.** The entities as one versioned JSON document (fields by canonical type, relations by target name, indexes, checks, defaults, filters, exposure), read back into metadata at run time, which `planSync` diffs. What is still a function gets a data form: named generators (`'uuidv7'`, `'now'`) for `onInsert`, `onUpdate` and defaults, named soft-delete strategies, context references in a filter's `where` (`{ authorId: { $context: 'userId' } }`), a serializable `sql` fragment, and JSON Schema for a Standard Schema that exports one. A function with no data form is refused by name on export; hooks stay in app code. Built test first: the round trip over every fixture entity lists what lacks a data form.
- **Live queries.** A read the client subscribes to, answered again when a write changes it, as a `GET ?q=` an `EventSource` opens. Re-running each subscription after uql's own writes, under the subscriber's context, comes first; an engine's change stream sees every writer, but SQLite, D1 and libSQL have none. [Open in the API layer](api-layer.md#open).
- **Row-level security, the rest.** SQL Server's native predicates, tenancy with composite tenant keys, transitions, field policies and `can()` on the client. [The design](row-level-security.md#next).
- **Named locks.** `querier.lock(name, { timeout })`, held to the end of the transaction, as Postgres's `pg_advisory_xact_lock` and MSSQL's `sp_getapplock` do. The migration lock in `migrationLock.ts` is the first half. An engine with no named lock takes a row with `SELECT ... FOR UPDATE`. Open: how a lock on a name shows in `$where`.
- **Installed views.** [The design](views.md#in-the-database). A plain view installed in the database, so a BI tool or another app reads it live by its name. Waits for an app that needs it: a materialized view is already a table any tool reads, as of its last refresh.
- **Oracle.** The half of [the design](oracle-mssql.md) not yet built; it inherits `MergeSqlDialect`'s paging and upsert.

## Settled

- **A stored aggregate kept by triggers is refused for now.** A read is about 70x faster on Postgres, but four concurrent writers on one parent take 200 to 260 s against 0.3 to 10 s without the trigger, since the row lock is held across each statement. Revisit with a batched or statement-level trigger, measured first.
- **One call, any transport, one protocol uql owns** (0.113.0). `api.call` takes a call as JSON and answers as JSON; HTTP is `{base}/:entity/:op`, a read `GET ?q=` or a JSON `POST`, a write a JSON `POST`; one client runs over any transport, answering what the pool answers; exposure is declared per entity and field. [The design](api-layer.md).
- **Rows cross the wire as the entity holds them.** JSON carries a `Date` and a `bigint` as text, so the API reads a call's query and rows and sends its result by the entity, and the client reads a result the same way (`http/wireRow.ts`): a `Date` field is a `Date` on both sides, a `bigint` exact.
- **A JSON payload is typed by a Standard Schema's output, and never parsed.** `f.json(schema)` takes Zod, Valibot or ArkType and types the column by its output; writes take the output, not the input, since an input that a transform or a default converts would store a document the read type misstates. Nothing is stored at run time, as with the removed `shape`. Writes are never validated against the schema: uql does not run `validate` on a write, a per-write cost it does not pay. A schema declaring no `types` property is refused by the weak-type check.
- **An id is either spelling in, one spelling out.** A by-id method takes `EntityId`, the union; `WrittenId` is the branch a write produced. Merging them refuses `findOneById(X, 'abc')` wherever the key cannot be named.
- **The key is a list.** Every path carries every column of it, a relation's child or junction row included (one column per key column, from `references`). `assertSoleId` refuses the rest by name, never taking the first column: MongoDB (a compound `_id` compares by field order; use a unique compound index) and a call by id (a composite row is reachable through `$where`).
- **Keys and indexes compare by columns, not names**, so a naming-convention change rewrites nothing.
- **A check is compared by name.** It is installed as `_uql_<table>__<label>_<hash>`, the hash of its SQL, as a trigger is: an edited check is a new name, the old one dropped. Safe mode adds the new one and holds the drop, as it does an index. Only a `_uql_` check is ever dropped; any other is warned about on a table declaring checks.
- **An unnamed partial index is named by a hash of its predicate**, as a check is: the engine's reprint never matches what uql wrote, so the name carries the edit and a changed `where` is a new index, the old one dropped. A named one's predicate is compared only by whether it is there, so adding or removing one rebuilds it. An index expression and a stored computed column's expression are not diffed (a fingerprint table is not worth keeping for an edit nobody has made); changing one is a written migration. An index's `where` is spelled as the predicate the query passes, never as `sql`, or the planner will not match the two.
- **SQLite alters a table by rebuilding it, foreign keys off.** Dropping the old table with them on deletes every `CASCADE` child and fails a `NO ACTION` one, and `defer_foreign_keys` stops neither; `PRAGMA foreign_keys` only switches outside a transaction. So the migration session switches it around the transaction and runs `foreign_key_check` before commit, and the rebuild carries a guard failing it wherever they stay on (D1, a remote libSQL).
- **An enum is a check, not a native type**: a named table constraint, since MariaDB names a column-level one itself. Changing its values replaces the check like any other.
- **A cursor page compares by the bounded chain `a <= x AND (a < x OR ...)` on every engine**, as a plain `$where`. A row-value comparison wins only on CockroachDB, by under half a millisecond, and only for keys running one way with no null. [The design](cursor-pagination.md).
- **A relation's `$limit` is each parent's share.** [The design](relations-in-one-statement.md).
- **A column shape is derived, never copied field by field.** Five hand copies each lost a different option.
- **A relation aggregate is declared, not spelled in a query.** A query-time `$max: { posts: ... }` would add a type parameter per op to all 36 read signatures; a `computed` field does more (`$where`, `$sort`, an exact type) at no such cost. `$sort` keeps the two a declaration cannot: `$count`, and a relation's nearest row to a vector.
- **A nullable column's property admits `null`, and only that.** Family types (`jsonb`, `numeric`) stay narrowable.
- **Every field option states where it applies**, in `FIELD_OPTION_FAMILY`; only contradictions are rejected.
- **No computed vector distance on D1 or MySQL.** Both store vectors as JSON, and a distance over it measured 10 ms to 230 ms a row. D1 points at Vectorize, MySQL at HeatWave.
- **A JSON update is folded to one write per path.** MySQL, MariaDB and SQLite bind by position, so no write may read what an earlier one left: `foldJson` works out every operator reaching a value another wrote before any SQL is written, and each write reads the column as stored. SQL Server, whose `JSON_QUERY` refuses a scalar, writes a key's value only where it is not NULL: a NULL one goes to a key that is not there, which `JSON_MODIFY` leaves alone.
- **No fuzzy-match or `$max`/`$min` update operator.** Neither has a portable form or a caller `sql` does not already serve.
- **A split write runs all or none, through one `runStatements` per querier.** One request on D1, Turso Cloud, libSQL and Neon over HTTP, a transaction elsewhere. [The design](split-writes.md).
- **Row-level security.** One policy as data, held by the querier on every engine and, on a `policies: 'native'` pool, by Postgres and CockroachDB themselves, bound per transaction; filters are convenience scopes again. [The design](row-level-security.md).
- **An entity is read-only when it says so or has no key.** `readOnly: true` is the data form of the `readOnly` brand, so a view with a key column is read-only too; neither is inherited, as a key is each entity's own. The one flag, `meta.readOnly`, holds the querier, the API and cascades; `whyReadOnly` names the cause. Every write refuses it by name in the querier (`writableMeta`), before any hook, on every engine. An entity with no key also refuses a by-id call through `soleIdOf`. It holds a to-one by its own foreign key and is reached by a to-many without cascade; a to-one reaching it, which tells no row from a row of nulls without a key, and a cascade into it are refused on first read. Its `wire` takes `'read'` alone, so the API refuses a client's write as it refuses any it does not expose. Its table has no primary key, and MongoDB reads its documents without `_id`.
- **A read-only entity takes no write at compile time.** Its type carries the `readOnly` brand, which `defineEntity` derives from `readOnly: true` or from having no key, and a decorated class declares, `[readOnly]?: true`. Each write's type parameter is held to `WritableEntity`, a constraint and not a conditional, so a generic caller's `E` still passes, at 11 instantiations over 800 queries (`ts.perf`). No general capability set.
- **Read replicas are an option of the pool, not a pool wrapping pools** (0.117.0). `{ replicas: [config] }` takes configs of the pool's own driver, each opened as the primary is (`AbstractDriverQuerierPool`), so a replica cannot drift from the primary's `policies`, naming or logging, and its queriers carry the pool's dialect, which keeps a call inside any of its transactions on that transaction's querier. A wrapper composing built pools was built first and dropped for that drift. A read, a stream and a `readOnly` unit of work run on a random replica, what `QUERIER_OPS` says reads; no picker until an app needs one. `pool.withQuerier(...)` reads past the lag on the primary.
- **What each querier method does to rows is one table, `QUERIER_OPS`**, total over `UniversalQuerier` and asked through `opDoes`: pool routing, the API's transaction choice, its HTTP methods and exposure all read it. A save or upsert is `['insert', 'update']`, not a kind of its own. The 22 pool delegators stay written out: building them from the table needs a cast.
- **No `await using` on a per-call path.** Lowered for the target, it cost every pool call 1.7 KB (`pgAllocation.test.ts`); `try`/`finally` costs nothing. A stream, which holds its querier across yields, keeps it.
