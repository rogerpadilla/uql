# UQL on Cloudflare D1

A Worker querying D1 through `D1QuerierPool`, with its schema generated by `uql-migrate` and applied by wrangler.

```sh
npm install
npm run db:apply   # wrangler d1 migrations apply DB --local
npm run dev        # http://localhost:8787/todos
```

## Changing the schema

Edit `src/entities.ts`, then:

```sh
npx wrangler d1 migrations create DB add_due_date
npx uql-migrate sync --dry-run >> migrations/0002_add_due_date.sql
npx wrangler d1 migrations apply DB --local    # and --remote once reviewed
```

`uql.config.ts` points the CLI at wrangler's local copy of the database, so the dry run prints only what that copy lacks. A D1 binding exists only inside a Worker, and D1 refuses the transaction `uql-migrate up` opens, so uql writes the SQL and wrangler applies it.

Before deploying, `npx wrangler d1 create uql-example` and put the id it prints in `wrangler.jsonc`.

Docs: https://uql-orm.dev/cloudflare-d1
